# Личная система и запуск на Windows

Расширение рассчитано на одного владельца: первый ID в `TELEGRAM_BOT_ALLOWLIST`.
Личные команды работают только в личном чате. Остальные ID сохраняют доступ
к старым командам бота и общей таблице задач; добавляй только доверенных людей.

## Подключение

1. Сохрани резервную копию текущей таблицы задач. Останови старый процесс бота.
2. Обнови код из ветки с изменениями. В папке проекта выполни `bun install --frozen-lockfile`.
3. В локальном `.env` оставь свои существующие секреты. Добавь:

   ```dotenv
   PERSONAL_SYSTEM_ENABLED=true
   ```

4. `STORAGE_PROVIDER=github`. `FILE_PATH` должен указывать на таблицу в
   **приватном** репозитории данных. Публичный репозиторий кода подходит для
   исходников; задачи и личное состояние хранятся отдельно.
5. Токен GitHub должен иметь доступ Contents: read/write и Metadata: read
   только к репозиторию данных. В коде, `.env.example`, сообщениях или экспортах
   секреты не размещаются. Для GitHub-кода и для данных используй раздельные права.
6. В PowerShell из папки проекта:

   ```powershell
   bun run build
   bun test
   bun run lint
   bun run start:polling
   ```

   Этот запуск сам отключает вебхук Telegram без удаления ожидающих сообщений
   и получает обновления напрямую. Публичный домен и туннель не нужны.
   Одновременно должен работать один экземпляр с этим Telegram-токеном.

7. Напиши боту `/settimezone Europe/Berlin`, затем `/system` и `/reminders on`.

Процесс должен оставаться запущенным. Сон, выключение и отсутствие интернета
останавливают доставку. Пропущенные часы не догоняются пачкой: окно доставки
5 минут. Для постоянной работы нужен постоянно включённый компьютер/сервер.
При выключенной личной системе старые команды и вебхук продолжают работать.

## Первые действия

```text
/inbox Открыть конспект и решить первую задачу #study
/inbox Подготовить сумку в зал #gym
/inbox Один шаг по проекту #project
/inbox Договориться о встрече #social
/focus
/step открыть конспект на нужной странице
/morning
```

В `/focus` выбери до трёх результатов кнопками. Приоритеты — выбор на этот день,
они не меняют даты задач и не означают три обязательных часовых блока.
Обычные текстовые сообщения тоже попадают во входящие без ИИ; сообщения внутри
существующих диалогов `/add` и `/edit` обрабатываются этими диалогами.

Для календарного события используй существующую `/add` с датой и временем,
затем подтверди добавление в Google Calendar кнопкой. План показывает
запланированные задачи из таблицы; внешние события Google Calendar обратно
в бот не импортируются. `/edit` меняет время, `/complete` завершает задачу.

После позднего подъёма — `/late`: один выбранный приоритет и будущие события.
Если нет сил — `/lowenergy`: один шаг на 5 минут с возможностью остановиться.
`/normal` возвращает обычный вид. Все задачи сохраняются; бот не переносит
встречи и не создаёт автоматически долг на завтра.

Вечером:

```text
/evening 3 | сделал один шаг | отвлекался на телефон | открыть конспект
```

Энергия 1–5, затем результат, препятствие и следующий шаг. Каждое поле до
400 символов; знак `|` разделяет поля. Повторная команда обновляет обзор дня.
Завтрашний `/morning` предложит указанный следующий шаг. `/week` показывает
последние семь календарных дней, включая текущий.

## Цели и направления

```text
/goals add study | решить 30 задач | 30 | три занятия по 25 минут в неделю
/goals
/goals progress ID 4
/inbox решить одну задачу #study #goal-ID
```

Подставь ID из `/goals`. Цель длится 90 календарных дней с даты создания;
число — измеримый целевой результат. Прогресс обновляется вручную как текущее
значение, а не прибавление. Связанные дела считаются отдельно по тегу цели.
Направления: `study`, `gym`, `project`, `social`, `life`.
`/goals remove ID` удаляет цель; задачи с её тегом остаются.

## Напоминания

```text
/reminders on
/reminders 09:00 21:30 18:00
/reminders quiet 22:00 08:00
/reminders weekday 0
/reminders lead 30
/reminders off
```

Три времени — утро, вечер, недельный обзор; день недели 0 — воскресенье,
1 — понедельник, …, 6 — суббота. Одинаковые начало и конец тихих часов отключают
тихий интервал. Все времена используют `/mytimezone`, включая переходы летнего
и зимнего времени. В тихие часы напоминания пропускаются.

Бот напоминает о событиях за указанное число минут (1–180). Дела без времени
входят в план, но не вызывают событийного напоминания. Выполненный утренний
план/вечерний обзор отключает соответствующий запрос на этот день.
История доставок хранится 14 дней. Конкурентные вызовы и перезапуск учитываются.
При подтверждённой ошибке отправки возможна повторная попытка через минуту.
При сбое между доставкой Telegram и сохранением подтверждения возможен дубль:
две внешние системы не поддерживают единую транзакцию.

В режиме webhook `/api/cron` защищён `CRON_SECRET`. Для личной системы его
необходимо вызывать каждую минуту через внешний планировщик. Исходный
`vercel.json` оставлен для прежнего расписания: сам по себе он **не обеспечивает**
утренние/вечерние/событийные напоминания новой системы. На Windows
`start:polling` уже содержит нужный планировщик; внешний cron не требуется.

Для Telegram webhook в личном режиме **обязателен `BOT_SECRET`**. Укажи его
в локальных настройках и повторно установи webhook штатной командой
`bun run set:webhook`, которая передаст секрет Telegram. Запросы без правильного
секрета отклоняются до чтения обновления. Polling не требует `BOT_SECRET`.
При включении напоминаний ID старых задач сохраняются до активации доставки.
Возврат через `/normal` меняет вид плана, сохраняя факт использования обоих
резервных режимов в недельной статистике.

Если Google Calendar уже создал событие, бот повторяет только сохранение его
ID в актуальную таблицу. При удалённой задаче или недоступном хранилище он
выдаёт ID события для восстановления в личном чате. Сохрани этот ответ;
проверь событие в календаре перед повторным добавлением.

## Сводка для коучинга

`/coaching` показывает точный состав файла и кнопку согласия. Затем
`/coaching export` выдаёт JSON в личном чате владельца. В экспорт попадают:

- агрегаты последних 7 дней: завершения по направлениям, количество планов
  и обзоров, средняя энергия, количество дней с резервным режимом;
- направления целей, числовые текущие/целевые значения и сроки.

Названия задач и целей, свободный текст обзоров, ссылки, Telegram ID,
GitHub/Telegram/ИИ токены и календарные реквизиты не экспортируются.
Перед загрузкой файла в ChatGPT проверь его содержимое. Передача происходит
только по твоему действию, у этого чата нет автоматического доступа к боту.
`/coaching off` отзывает согласие на будущий экспорт. Уже отправленные файлы
нужно удалять отдельно. Согласие на экспорт не меняет существующий `/add`:
эта команда по-прежнему использует настроенного ИИ-провайдера для разбора текста.

Постоянный канал чтения ChatGPT, публичный endpoint и автоматическая отправка
не включены. Следующий этап такой интеграции потребует отдельно выбранного
размещения, авторизации только на чтение согласованной сводки, срока доступа,
аудита запросов и независимого отзыва; ключ бота/репозитория не выдаётся клиенту.

## Совместимость и восстановление

`Id` и `CompletedAt` добавляются в конец Markdown-таблицы. Старые строки
читаются, ID назначаются при следующем сохранении/открытии плана. Перестановка
и переименование задачи сохраняют приоритеты благодаря ID. Не редактируй ID
вручную. Старые завершения без времени отмечаются как неизвестные в `/week`.
Удаление завершённых задач через `/clearcompleted` удаляет и их вклад в
статистику: сначала сохрани нужную недельную сводку.

Рядом с таблицей создаётся `personal-system.json`: настройки, планы, обзоры,
цели, согласие и статусы доставок. Не добавляй его в публичный репозиторий.
Файл проверяется по версии схемы и владельцу. Конфликт записи личного состояния
перечитывает актуальную версию; конфликт таблицы предлагает повторить действие.
Повреждённый/несовместимый JSON вызывает ошибку, а не заменяется пустым состоянием.

Чтобы откатить функции, выключи `PERSONAL_SYSTEM_ENABLED` и перезапусти прежний
код. Для полного восстановления таблицы возьми резервную копию. JSON можно
сохранить приватно и восстановить позже; отключение не удаляет историю.
Секреты храни в локальном `.env` и локальных файлах календаря, которые исключены
из Git. Старые версии кода не сохраняют новые столбцы: при откате держи копию
таблицы и личного состояния.
